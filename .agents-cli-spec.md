# Agent Spec — autoagents

## Overview

A personal autonomous assistant ("autoagents") that the user converses with over
**email** (v1), and later WhatsApp + voice (v2). It reads multimodal input
(text, images, PDFs, audio, short video), remembers the user across sessions,
stores documents in a searchable vector store, sends email on the user's behalf,
schedules tasks/reminders/followups and executes them when due, and summarizes
results back to the user.

The user gives **high-level instructions by email** ("follow up with John about
the invoice by Friday and summarize the replies"); the agent decomposes them
into tasks, executes over time, and reports back. The user can **start / pause /
stop** the agent with email admin commands.

## Architecture

Two deployables. Agent Runtime can't host webhooks/cron, so a thin Cloud Run
gateway fronts it.

1. **Agent brain — ADK on Agent Runtime**
   - Root agent (`gemini-3.5-flash`) + tools.
   - **Memory Bank** — long-term memory of the user (facts, preferences) across threads.
   - **Sessions** — native `VertexAiSessionService` (short-term context per thread).
   - **Vertex AI Search datastore** (`agent_platform_search`) — document RAG store.
   - Tools (ADK function tools, wrapped as an **MCP toolset** for reuse):
     - `send_email(to, subject, body, attachments?)` — Resend
     - `schedule_task(description, due_at, recurrence?)`
     - `list_tasks(filter)` / `cancel_task(id)`
     - `search_documents(query)` — RAG retrieval
     - `query_messages(filter)` — read the message log
     - (v2) `send_whatsapp(...)`, `make_call(...)`

2. **Event gateway — Cloud Run (FastAPI)**
   - `POST /inbound/email` — Resend inbound webhook. Verify signature → log inbound
     to Firestore → download attachments to GCS → check agent state → parse admin
     commands → call Agent Runtime `query` → send reply via Resend → log outbound.
   - `POST /tasks/run` — invoked by Cloud Scheduler (OIDC auth). Scan Firestore for
     due tasks/reminders/followups → execute (may call the agent) → send outputs → update status.
   - `GET /healthz` — health check.

3. **Data — Firestore (Native mode)**
   - `messages` — every message in/out across all channels: `{channel:
     email|whatsapp|call, direction: in|out, from, to, subject, body,
     attachments[], session_id, status, ts}`. Satisfies the "log every
     email/whatsapp/call" requirement; channel-agnostic so v2 just adds adapters.
   - `tasks` — `{type: task|reminder|followup, description, due_at, recurrence,
     status, payload, created_by, ts}`.
   - `agent_state` — single doc `{status: running|paused|stopped, reason, updated_at}`.
   - `contacts` — people for followups/reminders.

4. **Storage — Cloud Storage (GCS)** — inbound attachments (images/pdf/audio/video).
   Passed to Gemini multimodal inline / by URI; ingested into the RAG datastore.

5. **Cloud Scheduler** — cron → `/tasks/run` (every ~5 min) for due items; one daily
   digest job that summarizes activity and emails the user.

6. **Secret Manager** — Resend API key, inbound webhook signing secret.

## Example Use Cases

1. **Conversational email.** User emails a question with a PDF attached. Agent reads
   the PDF, answers, stores the PDF in RAG, remembers stated preferences in Memory Bank.
2. **Send on behalf.** "Email Sarah at sarah@x.com that I'll be 10 min late." Agent
   composes + sends via Resend, logs it, confirms to the user.
3. **Schedule + reminder.** "Remind me to renew the domain on July 20." Agent creates a
   reminder task; on/before due date the scheduler fires and the agent emails the reminder.
4. **Followup loop.** "Follow up with John about the invoice by Friday and summarize."
   Agent emails John, tracks replies (inbound matched to the task), summarizes, reports back Friday.
5. **Control.** User emails `!pause` → agent stops acting (still logs) until `!resume`.
   `!status` → agent replies with state + pending tasks. `!stop` → full halt.

## Constraints & Safety Rules

- **Admin = sender allowlist.** Only the user's verified address(es) may issue admin
  commands (`!pause`, `!resume`, `!stop`, `!status`) or instruct sending on the user's behalf.
- **No autonomous send to new external recipients without the instruction originating
  from the user.** Outbound email to third parties only when the user asked for it.
- **Respect agent_state.** `paused` → log inbound, take no action. `stopped` → ignore
  non-admin input.
- **Verify Resend webhook signature** on every inbound call; reject unsigned.
- **Log everything** in/out before and after agent action (audit trail).
- Secrets only in Secret Manager, never in code/`.env` committed.
- v2 WhatsApp method (official Cloud API vs unofficial) and call provider are
  **explicitly deferred** and must be re-decided before build.

## Success Criteria

- Round-trip email conversation works: inbound → agent → reply, both logged in Firestore.
- Multimodal: a PDF/image/audio/short-video attachment is correctly read and used.
- Memory: a fact stated in one email is recalled in a later, separate thread.
- RAG: a previously ingested document is retrieved to answer a question.
- Send-on-behalf: agent sends an email to a third party on instruction; logged.
- Scheduling: a task created now executes when due via the scheduler.
- Control: `!pause` / `!resume` / `!stop` / `!status` behave correctly.
